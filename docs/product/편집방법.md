# STRIX 제품 소개 발표자료 — 사용·편집 안내

이 폴더가 발표자료 전체입니다. **폴더째 USB에 복사해 가도 그대로 열립니다**(인터넷 불필요).
발표는 `index.html` 을 더블클릭해서 시작하면 됩니다.

본편 89장 + 부록 12장 = **101장**입니다.

---

## 1. 발표 중 키 조작 — PPT와 같습니다

| 하고 싶은 것 | 키 |
|---|---|
| **다음 장** | `→` `↓` `Enter` `Space` `PageDown` |
| **이전 장** | `←` `↑` `Backspace` `PageUp` |
| 처음 / 마지막 장 | `Home` / `End` |
| **개요** — 전체 슬라이드를 축소판으로 보고 클릭해 이동 | `O` |
| 전체화면 | `F` |
| **암전**(화면 끄기) — 아무 키나 누르면 복귀 | `B` |
| 인쇄 (슬라이드당 1페이지) | `P` |
| **편집 모드** | `E` |

리모컨(프레젠터)의 앞/뒤 버튼은 `PageUp`/`PageDown` 을 보내므로 그대로 동작합니다.

## 2. 화면에서 직접 고치기 — 편집기

**`E` 키를 누르면 편집 모드**가 됩니다. 한 번 더 누르면 발표 화면으로 돌아갑니다.
(편집기는 **내 PC에서 파일로 열었을 때만** 켜집니다. 홈페이지에 올린 것에는 나타나지 않습니다.)

| 하고 싶은 것 | 방법 |
|---|---|
| **고르기** | 클릭 · `Shift`+클릭으로 여러 개 · 빈 곳을 끌면 범위 선택 · `Tab` 으로 차례차례 |
| **옮기기** | 끌기 · 화살표키 1px (`Shift`+화살표 10px) |
| **크기** | 테두리의 네모 핸들을 끌기 · **이미지 모서리 = 비율 유지** · 이미지 상하좌우 = 자유 변형 |
| **글자 고치기** | **더블클릭** → 바로 타이핑. `Esc` 로 끝냄 |
| **글자 일부만 굵게·색** | 편집 상태에서 글자를 끌어 고른 뒤, 오른쪽 패널의 `굵게`·색 단추 |
| **그림 바꾸기** | 그림을 **더블클릭** → 파일 선택 (아래 3장 참고) |
| 되돌리기 / 다시 | `Ctrl+Z` / `Ctrl+Shift+Z` (50단계) |
| 복사 / 붙여넣기 / 복제 / 삭제 | `Ctrl+C` / `Ctrl+V` / `Ctrl+D` / `Delete` |
| 장 전체 관리 | `O` → 끌어다 놓기로 순서 변경 · 복사 · 삭제 |
| **저장** | `Ctrl+S` — `data/deck.js` 에 그대로 씁니다 |

- **끌면 분홍색 안내선**이 뜹니다. 다른 요소의 변·중심, 판면 여백, 화면 중심에 저절로 달라붙습니다.
  붙는 게 싫으면 `Alt` 를 누른 채 끄세요.
- 상자를 넘친 내용은 **빨간 테두리**로 표시됩니다. 위쪽 `전체 넘침 검사` 로 전 장을 한 번에 볼 수 있습니다.
  → **넘침은 가리지 않습니다.** 빨간 테두리가 뜨면 글을 줄이거나 상자를 키우세요.
- 저장하지 않고 창을 닫아도 **편집 중이던 내용은 남습니다.** 다음에 열면 위쪽에
  "저장하지 않고 닫은 편집 내용이 있습니다 — 복구 / 버리기" 가 뜹니다.

## 3. 이미지 교체

각 그림에는 **파일 이름**이 붙어 있습니다. 그 이름 그대로 `assets/user/` 에 저장하고
새로고침(F5)하면 바뀝니다. `.png` · `.jpg` 둘 다 됩니다.
편집 모드에서 그림을 **더블클릭**해 파일을 고르면 **선택 즉시 화면에 반영**되고,
`assets/user/` 폴더를 최초 한 번만 지정하면 그다음부터는 자동으로 그 폴더에 저장됩니다.

**이름 끝의 꼬리표가 무슨 그림인지 알려줍니다.**

| 꼬리표 | 뜻 |
|---|---|
| `-crop` | 앱 화면의 **일부만 잘라 확대**한 것 (예: `live-pushover-crop.png`) |
| `-cut` | 배경을 **투명하게 판** 것 — 간지의 컨투어 모델, 표지·마지막 장의 건물 |
| 없음 | 앱 화면 전체 · 계산서 · 검증 매뉴얼 쪽 등 원본 그대로 |

> 🚨 **꼬리표를 지우거나 바꾸지 마세요.** 같은 원본이 곳에 따라 다르게 쓰입니다 —
> 예를 들어 `live-tha` 는 본편에서는 잘라서(`-crop`), 부록에서는 통째로 쓰입니다.
> 이름을 합치면 한쪽이 조용히 깨집니다.

**`-cut` 그림을 새로 만들 때** — 앱에서 검은 배경(간지용) 또는 흰 배경(표지용)으로 찍은 뒤
`npm run product:assets` 를 돌리면 배경이 자동으로 투명해집니다. 손으로 누끼를 딸 필요가 없습니다.

## 4. ⚠ 검증 수치는 손으로 고칠 수 없습니다

검증 **21건 · 대조항목 131개**의 숫자는 `frontend/verification/records/*.json` 에서
**자동으로** 들어옵니다. 문장은 자유롭게 고칠 수 있고, **숫자 조각만** 잠깁니다.

- 잠긴 곳: 검증 표 두 장의 STRIX 값·기준값·오차·허용오차, 그리고 본문의 "21건 · 131개".
- 숫자를 바꾸려면 검증을 다시 돌려야 하고, 그러면 아래 명령 한 번으로 덱에 반영됩니다.

```bash
cd frontend
npm run deck:build      # records → data/verification.js 다시 굽기
```

**이 구조 덕분에 발표 자료의 숫자가 틀릴 수가 없습니다** — 같은 숫자를 두 곳에 적어 두지 않기 때문입니다.

## 5. 쪽번호는 저절로 맞습니다

장을 끼워 넣거나 순서를 바꿔도 번호를 손댈 필요가 없습니다. 규칙은 이렇습니다.

| 장 | 각주 줄 | 번호 |
|---|---|---|
| 표지 · 마지막 장 | 있음 | 없음 |
| 목차 · 간지(11장) | **없음** | — |
| 본문 | 있음 | `01 / 75` — **번호가 붙는 장만** 셉니다 |
| 부록 | 있음 | `A01 / REFERENCE` |

## 6. 폴더 구조 — 무엇을 고치면 무엇이 바뀌나

```
docs/product/
├─ index.html            ← 로더. 고칠 일 거의 없음
├─ engine/               ← 화면·기능 (기술사회 덱과 공용 자산)
│   ├─ deck.css   · deck.js       발표 (그리기 · 넘기기 · 인쇄)
│   ├─ editor.css · editor.js     편집기 (내 PC에서 파일로 열 때만 켜짐)
│   └─ skin-b.css                 ⚠ 자동 생성 — 직접 고치지 마세요
├─ data/
│   ├─ deck.js           ← ★ 발표 내용. 슬라이드의 원본 (편집기가 여기 씁니다)
│   └─ verification.js   ← ⚠ 검증 수치. 자동 생성 — 손대지 마세요
└─ assets/user/          ← ★ 그림 (여기가 항상 이깁니다)
```

슬라이드는 **1600×900 고정 캔버스**이고 모든 요소가 그 안의 좌표에 놓입니다 — PPT 와 같은 방식입니다.
화면 크기가 달라지면 캔버스가 통째로 비례 확대·축소되므로 **어느 PC에서도 보이는 모습이 똑같습니다.**

## 7. 개발자용 명령 (frontend 폴더에서)

| 명령 | 하는 일 |
|---|---|
| `npm run product:check` | **검수** — 원본 덱과 화소 대조 · 넘침 · 글 유실 · 인쇄 |
| `npm run product:check-editor` | **편집기 검수** — 선택·이동·크기·되돌리기·잠금·저장 왕복 |
| `npm run product:assets` | 그림 다시 굽기 (크롭 · 누끼) |
| `npm run product:skin` | Edition B 스타일시트 → `engine/skin-b.css` 다시 굽기 |
| `npm run product:convert` | ⚠ **1회성 이식 도구.** 원본 덱에서 `data/deck.js` 를 다시 만듭니다 — **편집분이 전부 사라집니다.** `--force` 없이는 안 돕니다 |

> `data/deck.js` 나 `engine/` 을 고쳤으면 반드시 `npm run product:check` 를 돌리세요.
